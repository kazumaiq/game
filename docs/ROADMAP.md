## 2. Тесты и деплой

- `tests/game-logic.test.js` содержит 22 пронумерованных сценария, включая ежедневные контракты.
- `.github/workflows/quality.yml` запускает `npm ci`, `npm test` и `npm run build` на Node.js 20.
- Первые CI jobs завершились через несколько секунд с нулём выполненных шагов и без назначенного runner. Это не результат unit-тестов: команды npm не запускались, поэтому автоматическую проверку пока нельзя считать пройденной. Нужно восстановить запуск hosted runner в GitHub Actions и повторить workflow.
- `tests/browser-qa.js` содержит сценарии браузерной проверки, но использует жёстко заданный Windows-путь к Chrome. Перед запуском из Linux CI его нужно сделать переносимым.
- После изменения меню надо отдельно проверить портретный и горизонтальный режим на iPhone Safari: нажатия, безопасные области, полноэкранный режим, возврат из настроек и загрузку сохранения.

## 3. Следующие задачи по приоритету

### P0 — корректность и мобильная проверка
1. Пройти полный путь «главное меню → новая игра → мойка → оплата → завершение смены».
2. Проверить окно бизнеса и меню настроек на iPhone, включая скролл, safe-area и закрытие.
3. Подтвердить зелёный CI-run для unit-тестов и Vite build.

### P1 — игровой цикл и баланс
1. Сделать browser QA переносимым и добавить smoke-тест меню, выбора локации и контрактов.
2. Проверить баланс ежедневных расходов, стоимости персонала, документов и наград контрактов на нескольких игровых днях.
3. Провести performance-pass на мобильных устройствах: число частиц, resize, память и длительность игровой сессии.

### P2 — расширение игры
1. Подключить облачные сохранения Supabase; сейчас LocalStorage остаётся основным хранилищем.
2. Пройти и протестировать сюжетные события конкурента «КлинАвто», ценовую войну и предложение о выкупе.
3. Продолжить художественный pass: более выразительные спрайты машин и объектов, анимации воды/пены и смена освещения.

## 4. Принцип статусов

«Реализовано» означает, что функция присутствует в коде. «Проверено» можно ставить только после успешного автоматического теста или фактической проверки соответствующего пользовательского сценария. Визуальное поведение iOS не следует считать проверенным одной лишь успешной production-сборкой.
